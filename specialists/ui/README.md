# `ui` specialist: training-task factory

156 original, automatically graded front-end tasks (vanilla JS logic, DOM components against a stub, accessible HTML
markup, CSS rules). Same idea as `phase0/harness2.py`: every task has a start state, a reference solution and hidden checks;
`validate.py` proves the start state FAILS and start+reference PASSES.

No model, GPU, browser, network, install or pull is used anywhere. Everything is stdlib / host node.

## Files

| file | purpose |
|---|---|
| `tasks.jsonl` | the task set (one JSON object per line, schema below), generated by `build.py` |
| `build.py` | imports the task modules and writes `tasks.jsonl` (`python3 build.py`) |
| `tb.py` | builder helpers (`js`, `py`, `jsfix`, `jsext`, `stub`); task modules append to `tb.TASKS` |
| `js_a.py` ... `js_g.py` | JS tasks (utils, validation, tables, state machines, DOM, fixes, extensions) |
| `html_a.py`, `html_b.py` | HTML/ARIA tasks (fix existing markup; write markup from a spec) |
| `css_a.py`, `css_b.py` | CSS tasks (write from spec; fix existing stylesheet) |
| `harness_ui.py` | `run_checks`, `grade(task, candidate_files)`, `make_prompt(task)`, `load_tasks()` |
| `lib/tlib.js` | JS test library: `test`, `finish`, fake `clock()`, tiny DOM stub `makeDom()`, `key()` |
| `lib/checklib.py` | Python checks: `Doc` (html.parser tree), `Css` (small CSS parser), `contrast`, `specificity`, `ok`/`finish` |
| `validate.py` | start-fails / reference-passes proof (`--only SUBSTR` to filter) |
| `validate_output.txt` | output of the last full validation run |

## Task schema (`tasks.jsonl`)

```
id            "ui-js-debounce", "ui-dom-tabs", "ui-html-fix-alt", "ui-css-grid-responsive", ...
kind          write | fix | extend | a11y | css
                write  - implement/build from a spec (JS stub or empty/skeleton HTML or CSS)
                fix    - JS code with a minimal injected bug; tests fail
                extend - working JS/HTML snippet that must get a new feature
                a11y   - existing HTML with accessibility defects to repair
                css    - write or repair a stylesheet
lang          js | html | css        (language of the main deliverable)
difficulty    easy | medium | hard
topic         short tag (forms, timing, state-machine, dom-component, aria, layout, responsive, ...)
files         {filename: content}    START state shown to the model (stubs throw 'not implemented')
instruction   natural-language task text (self-contained, states exports / names / exact strings)
visible       optional example(s) that must work (may be empty)
checks        {runner: "node"|"python", entry: "test_hidden.js"|"check_hidden.py",
               files: {entry: <hidden check source>}}      HIDDEN from the model
reference     {files: {filename: content}}   a solution that passes the checks
output_files  sorted list of file names the model is expected to return
```

`harness_ui.make_prompt(task)` builds the prompt text (files, instruction, examples, output format: one fenced block per
changed file whose first line is a `file: <name>` comment). `harness_ui.grade(task, {name: content})` merges the
candidate over `files`, runs the hidden checks and returns `(passed, output)`. Allowed output names match
`[A-Za-z0-9_][A-Za-z0-9_.-]*\.(js|html|css)`.

Checks print one `FAIL <name> - <reason>` line per failed assertion and `P/N passed`; exit code 0 iff all pass
(and at least one assertion ran, so an empty/never-run test cannot pass).

## How grading works (no browser, no downloads)

**JS (runner `node`)**: host node (`/opt/homebrew/bin/node`, override with `UI_NODE`) runs `test_hidden.js` with the
Node Permission Model: `node --permission --allow-fs-read=<tmpdir> --max-old-space-size=200`. No filesystem writes, no
network, no child processes, no workers; hard 30 s timeout; cwd is a throwaway temp dir. No local Docker image has node
and we do not pull, so this is the sandbox for JS (it is weaker than the Docker flags below; do not run untrusted code
outside this permission model). Tests are DOM-free except for `makeDom()` in `lib/tlib.js`, a ~100 line DOM stub
(elements, attributes, `classList`, `dataset`, `hidden`, bubbling `addEventListener`/`dispatchEvent`, `focus()` that
updates `document.activeElement`, `querySelector(All)` for `tag#id.class[attr=val]` compounds with descendant
combinators). Time is faked with `clock()` (global `setTimeout/clearTimeout/setInterval/clearInterval/Date.now`), so
timing tasks are deterministic and instant. Tasks that use timers say "use the global ..." because the fake clock is
installed on `globalThis`. Async tests are supported (`test` accepts async functions; do not mix with `clock()`).

**HTML/CSS (runner `python`)**: `python:3.12-slim` container, one at a time, with
`--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534:65534 --memory 256m --cpus 1
--pids-limit 64`, work dir mounted read-only at `/w`. `lib/checklib.py` provides `Doc` (stdlib `html.parser` tree with
`all/first/by_id/ids/label_text/name_of/headings`), `Css` (parses rules and nested `@media/@supports`, whitespace
normalised; `get(selector, prop, media)`, `order(...)`, `medias()`, `vars()`), `contrast()` and `specificity()`.
CSS values are compared in normalised form (lower case, collapsed whitespace, spaces around commas removed), so checks
accept the common spellings (`grid-template-columns: repeat(3, 1fr)` and `1fr 1fr 1fr`, `margin-inline:auto` and
`margin: 0 auto`, ...) where the task text allows alternatives.

## Usage

```
python3 build.py                    # regenerate tasks.jsonl from the task modules
python3 validate.py                 # all tasks (~2-3 min; python tasks start one container each)
python3 validate.py --only ui-dom   # subset
```

```python
from harness_ui import load_tasks, make_prompt, grade
t = load_tasks()[0]
prompt = make_prompt(t)                       # feed to a model
ok, out = grade(t, {"debounce.js": "..."})    # candidate files returned by the model
```

## Adding tasks

Add a call to `tb.js(...)`/`tb.py(...)` (or `jsfix`/`jsext`) in a module listed in `build.py`, run `python3 build.py`
then `python3 validate.py --only <id>`. A task is only valid if the start state fails and the reference passes. Write
instructions that fix every observable name, export and exact string the checks rely on; checks must not depend on
anything the prompt does not say.

## Known limits

- No real layout engine: CSS checks are structural (declared values, media contexts, source order, computed contrast
  and specificity), not rendered pixels. HTML checks are structural/ARIA, not a full accessibility-tree computation.
- `Css` ignores `@layer` precedence, nesting syntax, and shorthand expansion; tasks are written to avoid depending on them.
- The DOM stub is intentionally small (no `innerHTML`, no layout, no real focus rules, no `contains`).
- Tasks in a few families share structure (e.g. several state-machine tasks), but each has its own spec and tests.
- Reference solutions were validated against the hidden tests only; there is no mutation testing of the checks
  (unlike the `tests` kind in phase 0).
